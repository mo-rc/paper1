P12a was implemented and run locally under approved Amendment A7 (`docs/spec.md`, Amendment A7; proposal: `docs/a7_proposal.md`). The driver is `src/ub_rl/experiment_runner.py`; completed results and the D6 decision are recorded in `docs/verification_record.md` P12a and `results/p12a/`. No change was made to the checker, physics, objective, splits or their hashes. Runs used V only and single-threaded subprocesses.

**Pilots.** 3 entries × 3 seeds (0, 1, 2) × 10,000 **training** calls (A5's reading kept, A7 D4), provisional defaults (READ: `configs/*.json`), V only. Driver-generated config per entry: budget 10,000, checkpoint [10,000] with the actual training-call count at the checkpoint recorded, `budget_includes_eval` false, `eval_repair` false, `eval_contexts` "val" (F0/F2) or "val:100" (F1). Evaluation at the 10,000-call checkpoint — the same checkpoint as P13's — with the evaluation calls on top and counted into T: 10,000 + 1,000 (F0/F2), at most 10,000 + 1,400 (F1). **Recorded per pilot:** `run_meta.json` (P7 convention: status "complete", commit, SHA-256s), `run.jsonl`, the eval CSV (per context: index, output, feasible, repaired = output, repair_calls = 0, steps, calls — the F1 per-context steps/calls live here), metrics: raw feasibility over the feasible contexts (the R-C trigger input), raw mean gap over feasible outputs and the offline repaired gap (reported columns), F1 mean steps and mean calls.

**Tuning.** Per entry: 12 configurations, one seed (0), 3,000-call total budget each, `eval_repair` false, same eval sets. Checkpoint threshold = 3,000 − eval reserve for every entry: 2,000 for F0/F2 (exactly 2,000 calls of learning) and 1,600 for F1 (the reserve is at most 1,400, the difference recorded as `unused_calls`). The harness fires checkpoints after every step (`fire_checkpoints()` after each `agent.update()`, which returns None when the batch is not full; READ: `src/ub_rl/harness.py:373-381`), so the overshoot is 0 calls for F0/F2 and at most 1 for F1, independent of batch_size; the driver asserts total calls ≤ 3,000 on every tuning run — a failed assertion marks the run failed, not complete. **Draw:** configuration 1 = the provisional default (the A7 D5 incumbent); configurations 2–12 drawn uniformly without replacement from the search grid by `random.Random(707)` (stdlib, P7b convention; if the default's cell is drawn it is skipped). **Search spaces** (grids of existing config fields; the P11 provisional defaults marked *):

## 2. Driver design

Runnable module `src/ub_rl/experiment_runner.py` (`python -m ub_rl.experiment_runner pilot|tune|trigger|tables|bench`). It generates each run config (draws, the D4 budget arithmetic — tuning reserve; pilots 10,000 training — eval sets, `eval_repair` false), runs the P11 harness per config (`python -m ub_rl.harness config.json --outdir …`), computes the raw and offline repaired metrics of A7 D5, and skips a run only after validating its configuration, hashes and artifacts. `results/p12a/manifest.json` lists every planned run, its full field values and its metrics (results/ is git-ignored, VERIFIED: `.gitignore:1`); the `tables` subcommand writes `paper/tables/p12a_pilot_summary.csv`, `p12a_tune_summary.csv`, and `p12a_trigger.csv`. The raw and offline repaired gaps need the reference mass per context: read `results/audit/labels_val.csv` when present (hash-checked), else compute by checker enumeration on V (~2 s per 1,000 contexts at the P9-measured 1.81 ms per context; READ: `docs/verification_record.md` P9) — checker calls only, not RL budget; the source is recorded in the manifest.

## 3. Harness changes and tests

Two harness changes; the rest (the budget arithmetic, `"val:<n>"`, `budget_includes_eval`) already exists (VERIFIED: `src/ub_rl/harness.py:112-113, 207-215, 337-363`):

1. **`eval_repair`** (bool, default true = current behaviour). When false, `_evaluate` skips both repair loops (VERIFIED at `src/ub_rl/harness.py:246-272`), makes no repair checker call, and keeps the CSV schema (repaired = output, repair_calls = 0).
2. **End-after-final-evaluation rule in `budget_includes_eval` mode:** once the last configured checkpoint's evaluation has run, the run ends — no further training calls, even if the total is still below the budget — and `unused_calls` (= budget − training − eval) is recorded in the summary and the meta. (Today the loop would keep training past the final evaluation while the total is under the budget; VERIFIED at `src/ub_rl/harness.py:366-388`.)

Tests (`tests/test_harness.py`): `eval_repair` false → repair_calls = 0 and total calls = training + eval exactly; true unchanged (existing tests); "val:100" resolves to the first 100 rows of `val.csv` in file order; a tuning-shaped run (`budget_includes_eval` true, one checkpoint) ends after the final evaluation with total ≤ budget; an F1-shaped toy run whose evaluation costs less than the reserve ends with `unused_calls` > 0 and no training call after the final evaluation; a toy F0/F2 run with batch_size 128 and `budget_includes_eval` true fires its checkpoint at exactly the threshold (overshoot 0) and ends with total ≤ budget; fresh-process reproducibility (P12a-carried item). Tests (`tests/test_experiment_runner.py`): draw reproducibility (seed 707 → same 12, slot 1 = default, no duplicates); the D5 rule on synthetic metric rows (raw feasibility not lower, offline repaired gap ≥ 0.5 pp better, the repaired-feasibility filter, ties keep the incumbent, none passes → default), including a row with repair abstentions (gap averaged over the contexts where repair succeeds, abstention counts reported, repaired feasibility below the incumbent's → cannot pass); the offline repair on enumeration labels reproduces the registered mass-order repair; the D6 trigger on synthetic pilots (one entry ≥ 0.99 in all 3 seeds → no R-C; none → R-C); the D4 budget arithmetic per entry.

## 5. T accounting and the break-even envelope

**Components of T** (A5 convention; READ: `docs/spec.md` line 383): one training run up to the checkpoint + the entry's own tuning (12 × 3,000 = 36,000, evaluation included per A7 D4) + its own pilots (3 × (10,000 + evaluation) = 3 × 11,000 = 33,000 for F0/F2; at most 3 × 11,400 = 34,200 for F1 — A5's pilot reading, evaluation on top); no label calls (F0/F2 use none). Full-run checkpoint evaluations (`budget_includes_eval` false) are recorded in the metas; if counted they add ≈ 1,000 calls per checkpoint for F0/F2 and shift each N* up by ~76 per 1,000 calls, without changing any verdict below.

**Arithmetic.** Break-even against heuristic iteration (the cheapest conventional method; READ: `docs/spec.md` line 160): N* = T / (c_conv − c_learned), c_conv = the P7-measured heuristic mean on V = 14.19 calls (READ: `docs/verification_record.md` P7 table), c_learned = 1 for F0/F2 in the envelope (the verification call, zero repair — the lower bound; any repair raises N*). N_ref = 10,000.

| Checkpoint | T | N* = T / 13.19 | vs N_ref = 10,000 |
|---|---|---|---|
| 10,000 | 10,000 + 36,000 + 33,000 = 79,000 | 79,000 / 13.19 ≈ **5,989** | below; headroom ≈ 4,000 tasks |
| 50,000 | 50,000 + 69,000 = 119,000 | 119,000 / 13.19 ≈ **9,022** | below; headroom ≈ 978 tasks (~10 %) |
| 200,000 | 200,000 + 69,000 = 269,000 | 269,000 / 13.19 ≈ **20,394** | above, ≈ 2 × N_ref |

**Implication (arithmetic only, not assumed):** the efficiency claim can be arithmetically supported only at the 10,000- and 50,000-call checkpoints; the 10,000 checkpoint carries the only comfortable margin, 50,000 is borderline (any repair calls, or a comparison-set heuristic mean below 14.19, erodes it), and the 200,000 checkpoint cannot claim against N_ref = 10,000 even with c_learned = 1. The claim additionally needs the A5 condition — repaired feasibility 1.0 and mean gap ≤ 0.5 percentage points on the comparison set (READ: `docs/spec.md` line 387) — measured at P13; the pilots' raw metrics only preview it. **F1 note:** F1's per-design c is its measured mean step count plus repair calls (A5; READ: line 381), not 1 — steps are the F1 cost unit. P12a records per-context steps/calls in the pilots so the same table can be filled for F1 once its mean is known; with the heuristic at 14.19 calls and F1 walking from the same trial section, the denominator c_conv − c_learned is thin or negative unless F1's greedy path is markedly shorter. The pilot numbers decide; P12a assumes no conclusion.

## 6. Assumptions, risks, what P12a does not do

**Assumptions:** tuning seed 0 (the provisional config seed), pilot seeds 0/1/2, draw seed 707; incumbent = provisional default as slot 1; beta_anneal_steps = run budget in tuning configs; the selection gap is the offline repaired gap over all feasible contexts of the evaluation set (raw gap is a reported column); feasibility over the feasible V contexts (796 of 1,000; 71 of the 100-subset); labels_val.csv or a fresh checker enumeration as the reference-mass source; torch CPU determinism as P11.

**Risks:** 12 random draws may miss better grid corners (accepted — A5 fixes 12); single-seed tuning noise, the 100-context F1 noise with its zero-miss 0.99 bar, and F1's early-learning-speed selection (A7 D7); the offline repaired gap is computed from enumeration labels, so it measures the registered repair rule, not executed repair calls (the executed, counted numbers stay P13's); the PER-anneal-per-budget decision may interact with checkpoint behaviour (tested).

**Does not do:** no test file is read or evaluated anywhere (training reads `train.csv`, evaluation reads `val.csv` only; VERIFIED: `src/ub_rl/harness.py:59, 214`); no 200,000-call run; no P13; no freeze (P12b freezes the selected configurations, the R-C constants if triggered, and the test hashes); no spec.md edit (A7 is proposed in `docs/a7_proposal.md` and recorded on approval); no change to the checker, physics, objective, splits or hashes; no full-suite run in the plan phase.

**Carry to P12b:** the claim-eligible checkpoint(s) for N* — per section 5's arithmetic — are fixed at the P12b freeze, before any P13 run.
