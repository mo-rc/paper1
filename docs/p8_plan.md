## 2. The categorical-native GA (implemented and tested; superseded by A6 — kept, not run in full)

Uniform crossover + random-section mutation (A5). Everything else is decided and recorded so the implementation has no free choices:

- **Chromosome**: k genes, each a section index; the design of a chromosome is its lightest feasible gene, -1 if none.
- **Population and budget**: population size p; generations run while evaluations remain, so a run makes **exactly `budget` distinct section evaluations** (asserted). A carried elite is not re-evaluated and costs 0. **Duplicate rule: a section already evaluated in this run costs 0 — it is never re-evaluated — and the slot is redrawn from the unseen sections (deterministic), so each run ends at exactly `budget` distinct evaluations** — the same distinctness convention P7 used for random search (READ: `src/ub_rl/baselines.py` line 20). The final partial batch evaluates only the remaining budget genes.
- **Fitness**: feasible sections ranked by mass (lightest best, ties by smaller index); infeasible sections ranked below every feasible one by their largest utilisation overrun, max(0, U_max − 1), least-infeasible first, then mass. The GA may walk through infeasible sections, which matters at budget 20. **The run summary records that the GA's fitness uses utilisation overrun for infeasible sections.**
- **Uniform crossover**: per gene position, the child's allele is parent A's or parent B's with probability 1/2 per gene. **Random-section mutation**: with probability m per gene, the allele becomes a uniformly drawn section.
- **Selection**: tournament of size t on fitness; elitism e ∈ {0, 1} carries the best-seen individual into the next generation.
- **Configurations**: grid = p ∈ {2, 4, 5, 10, 20}, k ∈ {1, 2, 4, 8}, t ∈ {2, 3, 4}, m ∈ {0.05, 0.1, 0.2, 0.5}, c ∈ {0.5, 1.0}, e ∈ {0, 1} (960 combinations). The 12 tuning configurations are `random.Random("ga-configs-2026-11-15").sample(grid, 12)` over the product in this fixed order — deterministic, asserted by a test (spec §9: "12 configurations … drawn by a fixed seed").
- **Determinism**: the per-run RNG is `random.Random(f"{seed}|{config}|{context_id}")` — the same NumPy-version-independent device P7 used for random orders (READ: `src/ub_rl/baselines.py` lines 126–135). The same (seed, context, config) reproduces the same run and the same call count (tested).
- **Tuning selection (A5)**: each of the 12 configurations runs on all 1,000 V contexts at both budgets with seeds 0-2; score = V mean gap with feasibility not lower (the §9 selection rule); the best configuration is recorded with its tuning calls — 12 × 1,000 × 111 × 3 = 3.996 M evaluations (VERIFIED arithmetic, matches the trim's 4.0 M row). **The first drawn configuration is the default; a later configuration replaces the current best only if the V mean gap improves by at least 0.5 percentage points with feasibility not lower, applied in draw order. The rule is recorded in the meta.** Gap is the mean over rows where the configuration outputs a design; feasibility is the share of (budget, seed, context) rows with a feasible output. The selected configuration is then run on T1–T5 and the reference with seeds 0-9. **Budget |C| equals the enumeration optimum by construction (all 91 sections are evaluated) and is asserted per context; the summary records the budget-91 result as a cost data point, not a GA-quality result.**

**Equivalence to random search (A6, recorded in the run summary):** every evaluation of this variant is a uniform draw from the unseen sections — the initial draws, the random-section mutations, and the redraw of every already-evaluated crossover allele — so the evaluated set is a uniform sample without replacement of the budget size and the output is the lightest feasible among them: P7's random search without replacement (VERIFIED: `src/ub_rl/baselines.py` `random_search`, `src/ub_rl/baselines2.py` `ga`). Sampled evidence, T1 budget 20 (READ: `paper/tables/baselines2_run_output.txt`, commit 54db07a): exact 184 (18.4 %), false-abstain 194 (19.4 %), mean gap 15.023 % — against P7 random search T1 budget 20 (READ: `paper/tables/baselines1_run_output.txt`, commit b5aadf4): exact 3,607 (18.0 %), false-abstain 3,376 (16.9 %), mean gap 14.696 %. The variant is therefore not run in full; the mass-order GA of §2b replaces it.

## 2b. The mass-order GA (Amendment A6 — the one GA that runs; all choices decided here)

Integer genes along the mass-ordered catalogue; crossover and mutation use **index closeness**. Everything else carries over from §2 (budget rule, fitness, selection, elitism, determinism device, the A5 tuning protocol with the default rule, the budget-|C| cost-data-point note). New or changed decisions:

- **Chromosome**: k integer genes, section indices into the mass-ordered catalogue C (0..n−1); the design of a chromosome is its lightest feasible gene (unchanged).
- **Blend crossover (BLX-α)**: per gene position, parents a and b; child allele = round(a + β·(b − a)) with β drawn from U(−α, 1 + α) by the run RNG; **α = 0.5 fixed** (recorded; not part of the tuning grid). Clipped to [0, n−1]; when a = b the child keeps a (the mutation step then perturbs it). With probability c the child is crossed; otherwise it copies the tournament winner. Index closeness: the child lands between the parents' indices (plus at most half their distance beyond).
- **Index-step mutation**: per gene with probability m, the allele moves by δ drawn uniformly from {−s, …, −1, 1, …, s}; **s = 4 fixed** (recorded; ≈ 4.4 % of the catalogue — a local step). Clipped to [0, n−1]; if clipping returns the old allele, nudge +1 (or −1 at index n−1) so the mutation moves.
- **Duplicate rule (A6 wording)**: a section already evaluated in this run costs 0 and is never re-evaluated; the slot is redrawn as the **nearest unseen index** — the unseen index minimising |i − j| from the drawn index i, ties broken by the smaller index (decided, recorded). Every gene passes through this redraw before evaluation, so the run still ends at **exactly `budget` distinct evaluations** with the same pool mechanics as §2 (vectorised batches, partial final batch).
- **Configurations**: the same six parameters as §2 — p ∈ {2, 4, 5, 10, 20}, k ∈ {1, 2, 4, 8}, t ∈ {2, 3, 4}, m ∈ {0.05, 0.1, 0.2, 0.5}, c ∈ {0.5, 1.0}, e ∈ {0, 1} — **constrained to p × k ≤ 10** (the initial population spends at most half of the budget-20 evaluations; 8 of the 20 p-k combinations, 384 grid entries); the 12 tuning configurations are `random.Random("ga-mass-configs-2026-11-15").sample(grid, 12)` in the same fixed product order — the fixed draw seed is unchanged, asserted by a test. α and s are fixed outside the grid (recorded). The A5 tuning rule is unchanged and recorded in the meta.
- **Budgets 20 and |C|, seeds 0-9, T1–T5 + reference** (unchanged from A5). At budget |C| all sections are evaluated → equals enumeration, asserted per context, recorded as a cost data point.
- **Determinism**: the per-run RNG is `random.Random(f"{seed}|{config.id}|{context_id}")` (the same device as §2); same (seed, context, config) → same run and call count (tested).
- **The categorical-native GA**: the module and its tests stay in the suite (tested, kept); it is not run in full, and the run summary records its equivalence to random search (§2).

## 3. The MLP variant (i)

- **Labels**: the first 2,197 rows of `train.csv` in file order that have a feasible enumeration optimum (rows whose context has no feasible section are skipped in file order — decided, recorded in the meta). Label = the enumeration optimum section of the context, one-hot over the 91 sections. **Costing counts the skipped rows too (fixed here): every train row enumerated during the label scan costs its 91 enumeration calls, feasible or not.** Full enumeration costing = (n_labels + n_skipped) × 91; ordered-scan-with-certificate costing = sum of (optimum rank + 1) per label plus 91 × n_skipped (an ordered scan on an abstaining context scans the whole catalogue — VERIFIED: `src/ub_rl/baselines.py` `ordered_scan`). Rows beyond the scan stop are never enumerated and are not counted. Both costings recorded in the meta and the run summary.
- **Features**: 12 inputs — span, tributary width, dead, live, restraint ratio, one-hot deflection rule (3), one-hot depth cap (4, including "none") — z-scored with train-set statistics (recorded).
- **Model**: 91-way softmax MLP, cross-entropy, Adam, PyTorch 2.5.1+cpu (VERIFIED available in `rl_env`), `torch.set_num_threads(1)`, fixed data order, no shuffle. Training costs 0 checker calls — the labels are already costed.
- **Configurations**: grid = hidden ∈ {1×64, 1×128, 2×64, 2×128}, lr ∈ {1e-3, 3e-4, 1e-4}, epochs ∈ {20, 40, 80}, batch ∈ {32, 64}; the 12 tuning configurations are `random.Random("mlp-configs-2026-11-15").sample(grid, 12)` in this fixed order (same §9 rule). Each configuration trains once on the 2,197 labels and is scored on V; the V evaluation calls (1 verification per context plus repair steps) are counted and added to the classifier's cost (spec §9: tuning calls are added to the training cost; for the classifier the "training cost" is the label cost, decided and recorded). **The same selection rule as the GA applies: the first drawn configuration is the default and is replaced only on a ≥ 0.5 percentage-point V mean-gap improvement with feasibility not lower, in draw order; recorded in the meta.**
- **Seeds 0-9**: `torch.manual_seed(seed)` before init and training; identical rerun outputs asserted by a test (spec §11 treats the classifier as a stochastic comparator trained with seeds 0-9, so it needs ten seeds).
- **End-to-end evaluation** (spec §9 procedure, reused): argmax output → verify (1 call) → if infeasible, step up in mass order until feasible (each step 1 counted call) → abstain at the end of C. Gap is reported against the enumeration optimum (P7's reference, recomputed by the run itself).

## 6. Tests (tests/test_baselines2.py), mapped to the P8 acceptance line

Acceptance line (READ: `docs/patch_plan.md` P8): *every baseline reports feasibility, gap and calls on T1 to T5* — the run summary asserts exactly that, and the tests enforce the properties below.

1. GA determinism: same (seed, context, config) → identical run and identical call count on a rerun.
2. GA budget: exactly `budget` distinct evaluations per (context, seed, config), read from `CountingChecker` (both budgets); a recording checker shows no section is evaluated twice in one run (the duplicate rule: already-seen costs 0 and the slot is redrawn from unseen).
3. GA outputs: every returned design is feasible on recheck; abstain only when no feasible section was evaluated; gap ≥ 0 always (the optimum is the lightest feasible section).
4. **GA budget |C| equals the enumeration optimum on every seed and context run** (asserted by the runner too; the summary records it as a cost data point, not a GA-quality result).
5. GA config draw: the 12 configurations are stable across runs (fixed seed, fixed grid) and all 12 are distinct.
6. Tuning rule: the first drawn configuration is the default; a replacement needs ≥ 0.5 percentage points of V mean-gap improvement with feasibility not lower, in draw order (unit test on synthetic scores; the rule is recorded in the meta).
7. MLP labels: the scan enumerates train rows until the label count is reached; each label equals the enumeration optimum on that context; the costings count every enumerated row — (n_labels + n_skipped) × 91 full enumeration and sum(opt + 1) + 91 × n_skipped ordered scan (2,197 × 91 = 199,927 stays VERIFIED as the base-case arithmetic; the recorded costing adds the skipped rows).
8. MLP determinism: same seed → identical model weights and identical V/T1 predictions on a rerun.
9. MLP end-to-end: repaired outputs are feasible; abstention at the end of C; verification calls counted as 1 per output, 0 per abstain.
10. Store: every written file reloads through `load_results`; a file without its meta (or a stale meta) is rejected (P7 tests reused).
11. Splits: the run refuses to start if a split file differs from `data/splits/SHA256SUMS` (P7 test reused).
12. P7 snapshot: enumeration equals ordered scan on every evaluated context, and the per-file feasible counts reproduce the P7 snapshot (the P9 assertion pattern; READ: `docs/gate3_record.md` line 3).

Tests 1–6 above keep covering the categorical-native GA module (kept, tested, not run in full). The mass-order GA (§2b) additionally gets the same property tests — determinism, exactly-budget distinct evaluations with the nearest-unseen redraw, recheck, budget |C| equals enumeration — plus:

13. **Differs from random search with selection and crossover removed**: run the mass-order GA in mutation-only mode — config {p = 2, k = 1, t = 1, m = 0.5, c = 0, e = 0}, where "selection removed" is a tournament of 1 (a uniformly drawn parent) and "crossover removed" is c = 0 — at budget 20 on 50 sampled contexts, and P7's `random_search` at budget 20 with the same seed and context id. Record the draw order of the evaluated sections (recording checker); the statistic is the mean absolute step between consecutive draws. Assert on every one of the 50 contexts: mean step (mutation-only GA) < mean step (random search) — random draws have mean step ≈ n/3 ≈ 30, the GA's draws are index steps ≤ 4 or nearest-unseen redraws near the parents, so the inequality is deterministic and robust per seed.
14. **Beats random search at budget 20 on V**: the mass-order GA runs the A5 tuning on all 1,000 V contexts (12 configurations × seeds 0-2 × budgets 20 and |C|; the first drawn configuration is the default, replaced only on a ≥ 0.5 percentage-point V mean-gap improvement with feasibility not lower, in draw order); the configuration selected by the rule then runs at budget 20, seeds 0-9, on all 1,000 V contexts. 13. "Selection and crossover removed" (test 13) means tournament size t = 1 (uniformly drawn parent) and crossover probability c = 0, elitism e = 0 — no new code path, just that configuration.
14. The nearest-unseen redraw picks the unseen index minimising |i − j| from the drawn index, ties broken by the smaller index (tested for determinism).
15. Test 14 compares against the exact P7 values 14.823 % mean gap and 16.18 % false-abstain share with the P7 summary definitions (mean gap over reference-feasible rows where the method outputs a design); the tuned configuration is the honest comparison because it is selected by the same A5 rule the P8 run will use.
